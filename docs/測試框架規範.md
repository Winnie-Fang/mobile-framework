# Mobile Framework 測試框架規範

## 1. 框架概述

### 1.1 目的
本框架專為移動端應用程式自動化測試而設計，支援 iOS 和 Android 平台，主要針對國泰世華銀行企業金融 App (Global MyB2B) 進行功能測試。

### 1.2 技術架構
- **測試框架**: pytest + Appium
- **報告系統**: Allure
- **語言**: Python 3.8+
- **設計模式**: Page Object Model (POM)

## 2. 目錄結構規範

```
mobile-framework/
├── framework/          # 核心框架模組
├── module/            # 業務邏輯模組
├── page/              # 頁面物件 (POM)
├── testcase/          # 測試案例
├── data/              # 測試數據
├── utils/             # 工具模組
├── reports/           # 測試報告
└── log/               # 日誌文件
```

## 3. 編碼規範

### 3.1 命名規範
- **文件名**: 小寫字母和下劃線 `test_login.py`
- **類名**: 駝峰命名 `LoginPage`
- **方法名**: 小寫字母和下劃線 `login_with_credentials()`

### 3.2 測試案例命名
```python
def test_login_valid_credentials_success():
    pass
```

### 3.3 Page Object 規範
```python
class LoginPage(BaseObject):
    def __init__(self):
        super().__init__()
        self.set_remark("登入頁面")
        self.driver = DeviceManager.get_driver()
    
    def username_input(self):
        return BasicComponent(
            lambda: self.driver.find_element(AppiumBy.ID, "username"),
            remark=f"{self.remark()} > 使用者名稱輸入框"
        )
```

## 4. 測試標記規範

### 4.1 優先級標記
```python
@pytest.mark.P1  # 核心功能
@pytest.mark.P2  # 重要功能
@pytest.mark.P3  # 一般功能
```

### 4.2 平台標記
```python
@pytest.mark.ios      # iOS 平台
@pytest.mark.android  # Android 平台
```

### 4.3 功能模組標記
```python
@pytest.mark.login           # 登入功能
@pytest.mark.overview        # 總覽功能
@pytest.mark.payment         # 支付功能
```

## 7. 斷言規範

### 7.1 元素可見性斷言

### 7.2 文字內容斷言

## 9. 日誌規範

### 9.1 日誌級別
- `INFO`: 一般資訊記錄
- `WARNING`: 警告訊息
- `ERROR`: 錯誤訊息

### 9.2 日誌格式
```python
logging.info(f"執行操作: {operation_name}")
logging.error(f"操作失敗: {error_message}")
```

## 10. 報告規範

### 10.1 Allure 註解
```python
@allure.epic("移動端測試")
@allure.feature("登入功能")
@allure.title("有效憑證登入測試")
def test_valid_login():
    with allure.step("輸入使用者憑證"):
        pass
```

## 11. 執行規範

### 11.1 命令列執行
```bash
# 執行特定平台測試
pytest --platform=ios -m P1

# 執行特定功能測試
pytest --platform=android -m login

# 生成報告
python run.py
```

## 12. 最佳實踐

### 12.1 測試設計
- 遵循 AAA 模式 (Arrange, Act, Assert)
- 保持測試獨立性
- 使用有意義的測試名稱

### 12.2 效能優化
- 合理使用等待時間
- 避免不必要的截圖
- 優化元素定位策略

### 12.3 可維護性
- 定期重構測試程式碼
- 移除重複程式碼
- 保持程式碼簡潔
