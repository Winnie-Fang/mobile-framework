# MCP / Copilot 測試案例撰寫規範

本文件定義 MCP / Copilot 在自動化測試流程中，
**如何理解測試案例、如何執行 App、以及如何產出符合測試框架的測試腳本**。

---

## 一、AI 角色定義（強制）

MCP / Copilot 在本流程中 **只是一個測試案例產生器**，不是框架設計者。

你必須：
- 遵守既有測試框架
- 產出可直接使用的測試腳本
- 不自行設計新架構或簡化流程

---

## 二、輸入來源說明

MCP / Copilot 會同時讀取以下三類輸入：

1. **測試案例描述**
   - 讀取 testcaes.md ，只執行第 1 條測試案例。
   - 描述測試目的與操作流程
   - 不代表最終程式碼結構

2. **元素定位規範**
   - 讀取 locator_2.md 中元素定位的規範與限制
   - 定義可使用的定位策略
   - 只影響 locator 選擇，不影響測試流程設計

3. **測試框架撰寫規則（最優先）** 
   - 讀取自動化測試腳本撰寫指南.md 中的撰寫規則
   - 定義 Page / Component / Test 的撰寫規範
   - Page / Component / Test 分層
   - 命名、回傳型態、使用方式

👉 若三者衝突，**以測試框架規則為最高優先順序**

---

## 三、Appium MCP 執行階段規則

在手機上執行測試案例時：

- MCP 只負責：
  - 依照測試案例執行操作
  - 擷取指定元素的實際狀態或內容

- MCP 不得：
  - 根據 UI dump 自行設計 locator
  - 將執行細節直接寫進測試案例程式碼

執行結果 **僅作為產碼時的參考資訊**

---

## 四、測試腳本產出原則（核心）

### 1. 一律從 Page 開始

- 所有 UI 操作必須封裝在 Page
- Test 不得直接操作 driver 或元素

---

### 2. Page 撰寫規則

Page 必須：
- 繼承 `BaseObject`
- 支援 `__init__(role=None)`
- 封裝：
  - locator
  - wait
  - 行為方法
- 方法回傳 Component

Page 不得：
- 撰寫 assert
- 描述測試流程

---

### 3. 單裝置 / 多裝置處理原則

- Page 必須同時支援：
  - 單裝置（不指定 role）
  - 多裝置（由 Test 指定 role）
- Page 不得判斷裝置角色
- 裝置流程順序只存在於 Test

---

## 五、Test / Case 撰寫規範

Test 只能做三件事：

1. 初始化 Page（必要時指定 role）
2. 呼叫 Page 方法
3. 驗證 Page 回傳結果

Test 禁止：
- 使用 driver
- 寫 locator
- 等待元素
- 在 Test 中實作 Page 行為

---

## 六、產出限制與錯誤處理

- 不得產出框架未定義的寫法
- 不得補假資料或自行假設流程
- 若資訊不足，必須回傳：
  > 「需要補充測試框架或案例資訊」

---

## 最終目標

> MCP / Copilot 產出的測試腳本  
> 必須在 **不修改測試框架** 的前提下可直接執行。
