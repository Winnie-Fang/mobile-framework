## 專案概述

這是一個基於 **Appium + Pytest** 的行動裝置自動化測試框架，支援 **iOS** 和 **Android** 雙平台測試。

### 主要特色
- ✅ 支援單裝置與多裝置並行測試
- ✅ Page Object Model (POM) 設計模式
- ✅ 自動管理 Appium Server 生命週期
- ✅ 整合 Allure 測試報告
- ✅ 靈活的裝置配置管理

## 核心模組說明

### 1. DeviceManager (裝置管理器)

**位置**: `module/mobile/device_manager.py`

**功能**:
- 管理 iOS/Android 裝置連線
- 支援單裝置與多裝置模式
- 自動建立和管理 Appium Driver

**使用方式**:

#### 單裝置模式
```python
from module.mobile.device_manager import DeviceManager

# 自動偵測平台並建立 driver
driver = DeviceManager.get_driver()
```

#### 多裝置模式
```python
# 1. 配置 devices.json
{
  "defaultRole": "old",
  "devices": {
    "old": {
      "platform": "ios",
      "udid": "00008150-00154C6C0E46401C",
      "wdaLocalPort": 8102,
      "bundleId": "com.cathaybk.geb",
      "appiumPort": "4723"
    },
    "new": {
      "platform": "ios",
      "udid": "1C023E72-72E7-4A64-91A0-15484676A023",
      "wdaLocalPort": 8103,
      "bundleId": "com.cathaybk.geb",
      "appiumPort": "4723"
    }
  }
}

# 2. 在測試中使用
driver_old = DeviceManager.get_driver(role="old")
driver_new = DeviceManager.get_driver(role="new")
```

### 2. AppiumManager (Appium 伺服器管理)

**位置**: `module/mobile/appium_manager.py`

**功能**:
- 自動啟動/停止 Appium Server
- 檢查 Server 運行狀態
- 支援多 Port 配置

**使用方式**:
```python
from module.mobile.appium_manager import AppiumManager

appium = AppiumManager(port=4723)
appium.start()   # 啟動
appium.stop()    # 停止
appium.restart() # 重啟
```

### 3. BasicComponent (基礎元件)

**位置**: `module/mobile/component/basic_component.py`

**功能**:
- 封裝 Selenium WebElement 操作
- 提供統一的元件操作介面
- 內建等待機制與錯誤處理

**常用方法**:
```python
component.click()              # 點擊
component.send_keys("text")    # 輸入文字
component.clear()              # 清空內容
component.text                 # 取得文字
component.is_visible()         # 檢查可見性
component.assert_visible()     # 斷言可見
component.assert_clickable()   # 斷言可點擊
```

### 4. Page Object (頁面物件)

**位置**: `page/ios/login.py` (範例)

**設計模式**:
```python
from module.mobile.component.basic_component import BasicComponent
from module.mobile.device_manager import DeviceManager

class iOSLoginPage(BaseObject):
    def __init__(self):
        super().__init__()
        self.set_remark("GMB 登入頁")
        self.driver = DeviceManager.get_driver()
    
    def id_input(self):
        return BasicComponent(
            lambda: WebDriverWait(self.driver, 30).until(
                EC.visibility_of_element_located((AppiumBy.XPATH, '//XCUIElementTypeStaticText[@name="企業戶 ID / 統編"]/../following-sibling::XCUIElementTypeOther'))
            ),
            remark=f"{self.remark()} > 企業戶ID/統編"
        )
    
    def login_btn(self):
        return BasicComponent(
            lambda: WebDriverWait(self.driver, 30).until(
                EC.element_to_be_clickable((AppiumBy.IOS_PREDICATE, 'name == "登入"'))
            ),
            remark=f"{self.remark()} > 登入按鈕"
        )
```

## 測試撰寫方式

### 1. 基本測試結構

```python
import pytest
import allure
from module.mobile.navigator import Navigator

@pytest.mark.ios_login
@allure.epic("iOS")
@allure.feature("登入")
@allure.title("一般登入流程")
def test_ios_login():
    # 1. 初始化 Navigator
    navigator = Navigator().ios.zh
    
    # 2. 驗證初始狀態
    navigator.ios_login_page.login_slogan().assert_visible()
    
    # 3. 執行操作
    navigator.ios_login_page.id_input().click()
    navigator.ios_login_page.id_input().send_keys("65141474")
    navigator.ios_login_page.user_name().send_keys("admin01")
    navigator.ios_login_page.user_pwd().send_keys("Ab123456")
    navigator.ios_login_page.login_btn().click()
    
    # 4. 驗證結果
    assert navigator.ios_overview_page.to_do_list().is_visible()
```

### 2. 參數化測試

```python
test_data = [

```

### 3. Fixture 使用

**位置**: `testcase/conftest.py`

#### Session 級別 Fixture (Appium Server)
```python
@pytest.fixture(scope='session', autouse=True)
def appium_server(pytestconfig):
    """自動啟動/停止 Appium Server"""
    platform = global_adapter.CommonVar.PLATFORM.lower()
    appium = AppiumManager(4723)
    appium.start()
    
    yield
    
    appium.stop()
```

#### Function 級別 Fixture (Driver 清理)
```python
@pytest.fixture(autouse=True)
def teardown_driver():
    """測試後自動清理 Driver"""
    yield
    
    # 清理多裝置 drivers
    drivers = getattr(DeviceManager, "DRIVERS", None)
    if isinstance(drivers, dict) and drivers:
        for role, d in list(drivers.items()):
            d.quit()
        DeviceManager.DRIVERS = {}
    
    # 清理單裝置 driver
    driver = getattr(DeviceManager, "STATIC_DRIVER", None)
    if driver:
        driver.quit()
        DeviceManager.STATIC_DRIVER = None
```

## 執行測試

### 1. 使用 run.py

```python
# run.py
pytest.main([
    '--platform', 'ios',           # 指定平台
    '-m', 'ios_login',             # 指定 marker
    '--alluredir', './reports/allure_tmp'
])
```

執行:
```bash
python run.py
```

### 2. 使用 pytest 命令

```bash
# 執行所有 iOS 測試
pytest --platform=ios -m ios

# 執行特定測試檔案
pytest testcase/ios/test_ios_login.py --platform=ios

# 執行特定測試函式
pytest testcase/ios/test_ios_login.py::test_ios_login --platform=ios

# 執行 P1 優先級測試
pytest -m P1 --platform=android

# 平行執行 (需安裝 pytest-xdist)
pytest -n 2 --platform=ios
```

### 3. Pytest Markers

在 `pytest.ini` 中定義的標記:

```ini
markers =
    P1: Priority 1
    P2: Priority 2
    P3: Priority 3
    android: android platform
    ios: ios platform
    positive: 正向測試
    negative: 負向測試
    ios_login: iOS 登入測試
    gmb_login: GMB 登入測試
```

使用方式:
```python
@pytest.mark.P1
@pytest.mark.ios
@pytest.mark.positive
def test_example():
    pass
```

### 4. 查看 Allure 報告

```bash
# 生成並開啟報告
allure serve ./reports/allure_tmp

# 或生成靜態報告
allure generate ./reports/allure_tmp -o ./reports/allure_report --clean
```

## 最佳實踐

### 1. Page Object 設計原則

✅ **好的做法**:
```python
# 每個元件都有清楚的 remark
def login_btn(self):
    return BasicComponent(
        lambda: self.driver.find_element(AppiumBy.ID, "login_btn"),
        remark=f"{self.remark()} > 登入按鈕"
    )
```

❌ **避免的做法**:
```python
# 直接在測試中寫 locator
driver.find_element(AppiumBy.ID, "login_btn").click()
```

### 2. 等待機制

✅ **使用顯式等待**:
```python
WebDriverWait(self.driver, 30).until(
    EC.visibility_of_element_located((AppiumBy.ID, "element"))
)
```

❌ **避免硬編碼 sleep**:
```python
time.sleep(5)  # 不建議
```

### 3. 斷言方式

✅ **使用元件內建斷言**:
```python
navigator.ios_login_page.login_btn().assert_visible()
navigator.ios_login_page.login_btn().assert_clickable()
```

✅ **使用 pytest assert**:
```python
assert navigator.ios_overview_page.to_do_list().is_visible(), "處理清單未顯示"
```

### 4. 測試資料管理

✅ **使用參數化**:
```python
@pytest.mark.parametrize("username,password", [
    ("user1", "pass1"),
    ("user2", "pass2")
])
def test_login(username, password):
    pass
```

✅ **使用 JSON 配置檔**:
```python
# 從 data/json/ 讀取配置
with open("data/json/devices.json") as f:
    config = json.load(f)
```

### 5. 日誌記錄

```python
import logging

logging.info("開始執行登入測試")
logging.warning("發現非預期彈窗")
logging.error("登入失敗")
```

### 6. 多裝置測試注意事項

- 確保每個裝置使用不同的 `systemPort` (Android) 或 `wdaLocalPort` (iOS)
- 使用 `role` 來區分不同裝置
- 在 `teardown_driver` 中正確清理所有 drivers

### 7. 命名規範

- **測試檔案**: `test_*.py`
- **測試函式**: `test_*`
- **Page Object**: `*Page` (例如: `iOSLoginPage`)
- **變數**: 使用有意義的名稱 (例如: `login_btn` 而非 `btn1`)

## 常見問題排查

### 1. Appium Server 無法啟動
```bash
# 檢查 port 是否被佔用
lsof -i :4723

# 手動啟動測試
appium -p 4723
```

### 2. 找不到元素
- 檢查 locator 是否正確
- 增加等待時間
- 使用 `driver.page_source` 查看當前頁面結構

### 3. Driver 未正確清理
- 確認 `teardown_driver` fixture 正常執行
- 檢查是否有未捕獲的異常

### 4. iOS 實機測試問題
- 確認 `xcodeOrgId` 和 `xcodeSigningId` 設定正確
- 檢查 WebDriverAgent 是否正確安裝
- 確認裝置信任電腦

這個框架提供了完整的行動裝置自動化測試解決方案，主要特點:
